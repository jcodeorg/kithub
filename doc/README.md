# 📘 **【PoC計画書】Chromebook向けブラウザ完結型開発環境（Gitea + Drone CI + Web Serial）**

## 1. 概要・目的

本プロジェクトは、NPOと教育委員会が協働し、中学校の「技術・家庭科（計測・制御のプログラミング）」等において、**Chromebookとブラウザのみで完結する安全な開発環境**を構築・検証する実証実験（PoC）です。

GitHub等の外部商用クラウドを利用せず、自前環境で **「コード編集・管理（Gitea）」「自動ビルド（Drone CI）」「ESP32実機への書き込み（Web Serial）」** の一連の学習体験を安全かつ低コストで提供可能かを検証します。

特に本環境では、40名の生徒が一斉利用した際のサーバー負荷（メモリ枯渇）を回避するため、**エディタ（Web IDE）の処理をChromebookのブラウザ（クライアントサイド/WebAssembly）側で実行するアーキテクチャ**を採用し、最小のサーバーインフラで快適なレスポンスを実現します。

---

## 2. システム構成と開発・学習フロー

単なるGitサーバーにとどまらず、**「ブラウザでのコード編集」から「手元のマイコン（ESP32）への書き込み」までのラストワンマイル**をカバーする構成とします。

```text
[ Chromebook (生徒端末) ]
 ├── ① WebAssemblyベースWeb IDE (ブラウザ上で快適動作・構文補完)
 ├── ② Gitea API / OAuth 経由で Push
 └── ④ Web Serial API で ESP32 へダイレクト書き込み
        │
        ├── (Google OAuth 認証) ──> [ Gitea (リポジトリ管理) ]
        │                                   │
        │                              (Push検知)
        │                                   ▼
        └─────────────────────────> [ Drone CI (自動ビルド) ]
                                            │
                                   (.bin バイナリ生成)

```

### 学習・授業フロー（45分間）

1. **ログイン：** ChromebookのGoogle Workspaceアカウント（Google SSO）でGiteaにログイン。
2. **コード編集（クライアント動作）：** ブラウザ上で軽量動作するWeb IDE（Monaco Editor / VS Code for Webアーキテクチャ）でC++ / Arduinoコードを編集。入力補完やエラー判定はChromebook側で高速処理。
3. **Push・ビルド：** 編集したコードをGiteaへPush。裏側でDrone CIが自動で起動し、ESP32向けにコンパイル。
4. **実機書き込み：** Web Serial API（ESP Web Tools等）を利用し、CIで生成された `.bin` バイナリをブラウザからUSB経由でESP32実機へワンクリックで書き込み。
5. **評価・振り返り：** 教員はGitea上のリポジトリおよびビルドログで提出状況・学習進捗を確認。

## 3. 技術的工夫・課題対策（実証実験向け）

1クラス40名の生徒が一斉にアクセス・操作した際の不具合を防ぐため、以下の対策を講じます。

| 課題 | 原因 | 本実証実験での技術的対策 |
| --- | --- | --- |
| **40名一斉利用によるサーバーメモリ枯渇** | 従来の重いWeb IDE（サーバー側Node.js起動型）だと1人あたり数MB〜数百MBを消費し8GB VPSでは即パンクする | **エディタ描画・入力補完処理をChromebook（ブラウザ/Wasm）側に肩代わりさせる構成を採用。** サーバー側のメモリ消費をほぼゼロに抑え、40名同時接続でも安定稼働させる。 |
| **一斉ビルド時のサーバーハングアップ** | 40名同時に `git push` するとC++コンパイルでCPU/メモリが枯渇する | Drone CIの**同時実行ランナー数を「2〜4」に制限**し、キューイング処理を実施。コンパイルキャッシュ（ccache）を適用し1人あたりのビルド時間を短縮する。 |
| **ブラウザからの実機書き込み** | CIで生成された `.bin` を手元で書き込む手段が必要 | **Web Serial API**を活用したブラウザ書き込みツールを標準連携させ、Chromebookから直接シリアル通信でESP32へ焼く。 |
| **校内ネットワーク帯域の圧迫** | CI実行時に外部からライブラリや依存関係を都度取得してしまう | CI用Dockerイメージ内に**ESP32ツールチェーンおよび基本ライブラリをプリインストール**し、外部通信を最小化する。 |

## 4. 検証用インフラと最低運用コスト

クライアントサイド（Chromebook）のリソースを有効活用する設計により、1クラス（40名）の実証実験を安価なVPS 1台（Docker Compose構成）で安定運用できます。

### 検証用サーバー構成（1クラス40名用）

* **スペック：** 4コア / 8GB メモリ / 100GB NVMe SSD（例: Xserver VPS / さくらのVPS 等）
* **OS / 環境：** Ubuntu Linux + Docker / Docker Compose

### 最低月額インフラコスト（目安）

* **統合VPS利用料（4コア/8GB）：** 約 3,000 円〜3,500 円／月
* **ドメイン・SSL証明書費用：** 約 200 円／月（Let's Encrypt等を利用）
* **合計（インフラ原価）： 約 3,200 円〜3,700 円／月**
* *(※検証期間2ヶ月の場合、総インフラ費は約7,500円程度)*

## 5. 本PoCのメリット・教育委員会への提示ポイント

* **サーバーインフラの超軽量化・低コスト化：**
エディタ処理をChromebook側に委ねるアプローチにより、高価なクラウドサーバーを契約することなく、月額数千円レベルのインフラで1クラス40名の快適なWeb IDE利用を実現。
* **高い安全性（個人情報保護）：**
生徒の氏名・コード等は特定の検証用サーバー内に閉じ、Google OAuthによる認証保護を実施。外部商用サービスへのデータ流出リスクを回避。
* **GIGAスクール端末（Chromebook）の性能をフル活用：**
ブラウザとUSB接続のみで動作するため、Chromebookへの追加アプリインストールや環境汚染がゼロ。
* **本格的なSTEM／DevOps教育体験：**
単なるブロックプログラミングにとどまらず、プロ開発現場に近いGit/CIの仕組みを安全に体験可能。
* **教育委員会側の初期導入ハードルの低さ：**
実証実験期間中のインフラ費用が極めて安価であり、自治体予算の枠組み内で柔軟に試行可能。

4. **模擬授業・本番運用：** 協力校での1クラス実証授業（45分）の実施とアンケート回収。
